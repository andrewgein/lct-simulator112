# Перенос ранее выданных сертификатов

Схема `course-service` создаёт таблицу `certificates` миграцией V8. До переключения frontend/API на новый сервис перенесите существующие строки из `review` в `course`: таблицы имеют одинаковые имена и набор колонок. Используйте строки подключения PostgreSQL (`postgresql://…`), не JDBC-адреса приложения. Например, при остановленной выдаче новых сертификатов:

```sh
pg_dump "$REVIEW_DB_URL" --data-only --column-inserts --table=public.certificates \
  | psql "$COURSE_DB_URL"
```

Проверьте количество строк и выборочно IDs в обеих базах. Не удаляйте старую таблицу до завершения переноса и проверки. Миграцию `review-service/V5__add_certificates.sql` нельзя удалять: Flyway уже применил её в существующих базах.

После коммита оценки `review-service` синхронно уведомляет `course-service` через gRPC; тот получает оценки пакетом через gRPC и выдаёт сертификат. Если процесс остановится после коммита оценки, но до уведомления, вызов потеряется: периодическая сверка или иной механизм повторной обработки понадобится для гарантии доставки. Событие `certificate.issued` для уведомлений публикуется после коммита без transactional outbox и имеет тот же риск.
